Цепочка: от базы данных до браузера

Таблица в базе данных (catalog_product)
Хранит строки с товарами: название и точную цену.
Модель Product (catalog/models.py)
Описывает поля товара в коде на Python. Структура модели не менялась с занятия 10, поэтому новые миграции на этом занятии не требуются.
Запрос в views.py (Product.objects.filter(...).order_by(...))
Отбирает нужные строки из базы данных по условию и задаёт порядок сортировки.
Словарь контекста {'products': products}
Упаковывает отобранные товары и передаёт их шаблону под понятным именем.
HTML-шаблон (catalog/templates/catalog/product_list.html)
Генерирует готовую веб-страницу: обходит товары циклом и подставляет их названия и цены в карточки.
Браузер покупателя
Получает итоговый HTML-код со стилями и рисует красивую сетку товаров.

1. Фильтрация и сортировка: filter и order_by

В занятии 10 мы получали все товары подряд через Product.objects.all(). На этом занятии мы уточнили запрос:

products = Product.objects.filter(price__lte=100).order_by('price', 'id')

Что означает price__lte=100?

В Django двойное подчёркивание __ отделяет имя поля модели (price) от операции сравнения (lookup):

  • lte — сокращение от less than or equal (меньше или равно, <=). Условие price__lte=100 оставляет товары с ценой до 100 ₽ включительно. Товар ровно за 100 ₽ попадёт в список!
  • gte — greater than or equal (больше или равно, >=).
  • lt — строго меньше (<).
  • gt — строго больше (>).

Если вы знакомы с языком SQL, это прямо соответствует части WHERE price <= 100.

Что означает order_by('price', 'id')?

Метод order_by задаёт порядок сортировки строк:

  • 'price' сортирует от меньшей цены к большей (от дешёвых к дорогим). Это соответствует ORDER BY price ASC в SQL.
  • 'id' — второй критерий (tie-breaker): если у двух товаров одинаковая цена (например, тетрадь за 80 ₽ и альбом за 80 ₽), первым пойдёт тот, который был добавлен в базу раньше (у кого меньше номер id).
  • Обратный порядок (от дорогих к дешёвым): задаётся знаком минус перед именем поля — order_by('-price', 'id').

Вот как выглядела функция home в catalog/views.py на первом шаге с текстовым выводом:

from django.http import HttpResponse
from .models import Product

def home(request):
    products = Product.objects.filter(price__lte=100).order_by('price', 'id')
    lines = []

    for product in products:
        lines.append(f'{product.name} — {product.price} ₽')

    text = '\n'.join(lines) or 'Товаров пока нет'
    return HttpResponse(text, content_type='text/plain; charset=utf-8')

2. Где Django ищет шаблоны и вызов render()

Текстовая строка удобна для быстрой проверки, но настоящему сайту нужен HTML. В Django за отображение страниц отвечают шаблоны (templates).

Где должен лежать файл product_list.html?

Стандартная настройка Django (APP_DIRS: True в settings.py) ищет файлы шаблонов внутри папок templates каждого установленного приложения. Правильный путь относительно папки с manage.py:

mysite/
├── manage.py
└── catalog/                      ← папка приложения
    └── templates/                ← стандартная папка шаблонов Django
        └── catalog/              ← подпапка с именем приложения
            └── product_list.html ← наш файл шаблона
Зачем папку catalog повторять внутри templates?

Когда в проекте будет несколько приложений (например, catalog, users, orders), Django собирает шаблоны со всех приложений в одно общее пространство имён. Если бы файлы лежали просто в catalog/templates/product_list.html, Django при запросе product_list.html мог бы перепутать их с шаблоном из другого приложения. Вложенная подпапка catalog/ защищает от таких конфликтов.

Упрощённый вариант (без подпапки):
В небольших проектах, пока приложение одно, шаблон можно положить прямо в catalog/templates/product_list.html (без вложенной папки catalog). Тогда во views.py вызов сокращается до render(request, 'product_list.html', ...). Оба варианта верны — главное, чтобы путь в render() в точности совпадал с тем, как файл лежит внутри папки templates/.

Функция render()

В файле catalog/views.py импортируем render из модуля django.shortcuts:

from django.shortcuts import render
from .models import Product

def home(request):
    products = Product.objects.filter(price__lte=100).order_by('price', 'id')
    return render(request, 'catalog/product_list.html', {'products': products})

Разберём аргументы render():

  1. request — входящий HTTP-запрос от браузера;
  2. 'catalog/product_list.html' — путь к шаблону относительно папки templates/;
  3. {'products': products} — словарь контекста. Слева ключ 'products' — под этим именем выборка будет доступна в HTML-шаблоне. Справа значение products — переменная с данными из базы.

3. Шаблонизатор Django: циклы и переменные

В шаблоне Django обычный HTML объединяется со специальными тегами шаблонизатора (DTL — Django Template Language):

{% raw %}

Переменные: {{ ... }}

Двойные фигурные скобки подставляют значение переменной в HTML. Например:

<span class="product-name">{{ product.name }}</span>
<span class="product-price">{{ product.price }} ₽</span>

Если product.name равно «Тетрадь», в браузер отправится чистый HTML: <span class="product-name">Тетрадь</span>.

Теги управления: {% ... %}

Фигурные скобки со знаками процентов задают управляющие конструкции: циклы и условия.

Цикл for:

{% for product in products %}
    <li>
        <span class="product-name">{{ product.name }}</span>
        <span class="product-price">{{ product.price }} ₽</span>
    </li>
{% endfor %}

Цикл повторяет разметку внутри блока для каждого товара из переданного списка products. Тег {% endfor %} обязательно закрывает цикл (в отличие от обычного Python, где границы определяются отступами).

Условие if / else:

{% if products %}
    <ul class="products">
        {% for product in products %}
            <li>...</li>
        {% endfor %}
    </ul>
{% else %}
    <p>По этой цене товаров нет.</p>
{% endif %}
{% endraw %}

Если выборка не пуста, отрисовывается список <ul>. Если ни один товар не подошёл под фильтр — выводится понятный текст без ошибок.

4. Оформление карточек на CSS

Чтобы товары отображались не просто списком в столбик, а удобной сеткой карточек, мы использовали CSS Flexbox:

/* Контейнер карточек: выстраивает элементы в ряд с переносом */
.products {
    display: flex;
    flex-wrap: wrap;
    gap: 12px;
    margin: 0;
    padding: 0;
    list-style: none;
}

/* Сама карточка товара */
.products li {
    width: 220px;
    max-width: 100%;
    padding: 16px;
    border: 1px solid #bacbc0;
    border-radius: 12px;
    background-color: #ffffff;
    overflow-wrap: anywhere;
}

.product-name {
    display: block;
    margin-bottom: 6px;
    font-weight: bold;
}

.product-price {
    color: #1d503a;
}
  • display: flex — включает гибкую блочную модель для списка;
  • flex-wrap: wrap — разрешает перенос карточек на новую строку, если они не помещаются в ширину экрана;
  • gap: 12px — делает аккуратный промежуток между карточками как по горизонтали, так и по вертикали;
  • border-radius: 12px — скругляет углы карточек;
  • overflow-wrap: anywhere — защищает верстку: если у товара будет слишком длинное слово, оно перенесётся и не сломает карточку.

5. Форма бюджета: запрос GET

В конце занятия мы начали добавлять форму бюджета, чтобы покупатель мог сам ввести предельную сумму:

{% raw %} 
<form class="budget-form" method="get">
    <label for="max-price">Бюджет до, ₽</label>
    <input id="max-price" name="max_price" type="number"
           min="0" max="999999" step="1" value="{{ max_price }}">
    <button type="submit">Показать</button>
    <a href="/">Сбросить</a>
</form>
{% endraw %}

Как параметры попадают из формы в views.py?

  1. Атрибут method="get" указывает браузеру отправить введённые данные прямо в адресной строке URL.
  2. Атрибут name="max_price" задаёт имя параметра в адресе. Например, при вводе числа 60 браузер перейдёт по адресу http://127.0.0.1:8000/?max_price=60.
  3. Ссылка «Сбросить» ведёт на чистый адрес /, возвращая каталог ко всем товарам.

В функции home мы читаем этот параметр через словарь request.GET:

def home(request):
    max_price = request.GET.get('max_price', '')
    products = Product.objects.order_by('price', 'id')

    # Если параметр передан, преобразуем его из строки в число и фильтруем
    if max_price:
        budget = int(max_price)
        products = products.filter(price__lte=budget)

    return render(request, 'catalog/product_list.html', {
        'products': products,
        'show_budget': True,
        'max_price': max_price,
    })

Частые ошибки и их решение

TemplateDoesNotExist
Django не нашёл файл шаблона. Проверьте:
  • Соответствие путей: если шаблон лежит в catalog/templates/product_list.html, в views.py должно быть 'product_list.html'; если внутри есть подпапка, то 'catalog/product_list.html';
  • Папка templates пишется во множественном числе;
  • Приложение 'catalog' добавлено в INSTALLED_APPS в файле settings.py.
Заголовок виден, но карточки пустые («По этой цене товаров нет»)
Проверьте имя переменной в словаре render(): оно должно в точности совпадать с циклом в шаблоне — {'products': products} и {% raw %}{% for product in products %}{% endraw %}. Также проверьте порог цены: возможно, все товары в базе стоят дороже установленного лимита.
ValueError: invalid literal for int() with base 10
Возникает, если в адрес вручную ввести не число, например /?max_price=abc. Функция int('abc') падает с ошибкой. На следующем занятии мы разберём проверку max_price.isdecimal() перед вызовом int().
Браузер не видит изменения в коде
Проверьте, сохранён ли файл (Ctrl+S). Если сервер запускался с параметром --noreload, перезапустите его в обычном режиме python manage.py runserver.

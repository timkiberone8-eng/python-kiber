Перед началом

Это задания для закрепления материала занятия 15 ноября: фильтрация товаров, сортировка и вывод в виде карточек HTML-каталога.

Открой свой учебный проект в VS Code, активируй рабочее окружение Python и запусти сервер разработки из папки с manage.py:

python manage.py runserver

Проверь в браузере адреса http://127.0.0.1:8000/ и http://127.0.0.1:8000/admin/. Если сервер выдаёт ошибку или страницы не открываются, сверься с разделом частых ошибок в конспекте.

Олимпиадная разминка

В начале занятия мы разбирали комбинаторную задачу на подсчёт вариантов. Проверь свой ответ в интерактивном поле ниже:

Какая именно цифра решает, чётное ли число? С какой позиции удобнее начать выбор? Сколько вариантов подходит на последнее место и сколько остаётся для остальных?
Разбор решения:
1. Чётность числа определяется исключительно его последней цифрой. Из набора цифр (3, 4, 5, 6) чётными являются только 4 и 6. Значит, на последнее место есть 2 варианта.
2. Выбираем первую цифру (сотни): одну цифру мы уже поставили в конец, поэтому из 4 цифр остаётся 3 варианта.
3. Выбираем среднюю цифру (десятки): две цифры уже использованы, остаётся 2 варианта.
4. По правилу произведения перемножаем количество вариантов для каждой позиции: 3 × 2 × 2 = 12 чисел.
(Все подходящие числа: 354, 364, 534, 564, 634, 654, 346, 356, 436, 456, 536, 546).

Обязательный минимум

Выполни по порядку шаги ниже на своём компьютере:

  1. Убедись, что HTML-каталог работает. Открой http://127.0.0.1:8000/. На странице должен быть заголовок «Каталог товаров» и плитка карточек. Если выводится только текстовая строка без оформления, добавь HTML-шаблон по шаблону из конспекта.
  2. Измени порог фильтра. В файле catalog/views.py найди функцию home. Замени число в условии фильтрации: 
    products = Product.objects.filter(price__lte=50).order_by('price', 'id')
    Сохрани файл (Ctrl+S), обнови страницу в браузере. Убедись, что товары дороже 50 ₽ исчезли со страницы, а товары с ценой до 50 ₽ остались.
  3. Поменяй порядок сортировки. Поставь знак минус перед именем поля: 
    products = Product.objects.filter(price__lte=100).order_by('-price', 'id')
    Обнови страницу. Убедись, что порядок карточек перевернулся: теперь в начале списка идут самые дорогие товары из подходящих, а в конце — самые дешёвые.
  4. Проверь граничное значение (lte). В админке (/admin/) добавь товар с ценой ровно 100.00 ₽ (например, «Линейка»). Верни в коде фильтр price__lte=100 и обнови главную. Линейка должна отображаться в каталоге, потому что lte означает «меньше или равно».
  5. Проверь пустую выдачу. Установи заведомо низкий порог цены, например price__lte=5 (если у тебя нет товаров дешевле 5 ₽). Обнови главную страницу. Убедись, что страница не падает с ошибкой, а аккуратно выводит сообщение: «По этой цене товаров нет.».

Минимум считается выполненным, когда ты самостоятельно меняешь фильтр и сортировку в коде, видишь правильное изменение карточек в браузере и можешь объяснить эффект каждой строки.

Дополнительно — для тех, кто хочет больше

1. Двойное условие (диапазон цен от 50 до 150 ₽)

В методе filter можно передавать несколько условий через запятую. Запятая означает логическое «И» (оба условия должны выполниться одновременно):

products = Product.objects.filter(price__gte=50, price__lte=150).order_by('-price', 'id')
  • price__gte=50 — цена больше или равна 50 ₽;
  • price__lte=150 — цена меньше или равна 150 ₽;
  • order_by('-price', 'id') — сортировка от дорогих к дешёвым.

Добавь в админке «Ластик» за 50 ₽ и «Пенал» за 150 ₽. Проверь: оба ли товара видны на странице? Товар за 30 ₽ (ручка) и товар за 500 ₽ (рюкзак) должны быть исключены.

2. Попробуй передать параметр через URL

Если ты уже подключил форму бюджета из 5-го раздела конспекта, открой в браузере вручную:

http://127.0.0.1:8000/?max_price=80

Проверь, как отобразились товары и какое число подставилось в поле формы.

Самопроверка

1. Почему для фильтрации и HTML-шаблона не потребовались команды makemigrations и migrate?

Миграции нужны только тогда, когда меняется структура таблиц в базе данных (добавление новых полей модели, удаление полей, смена их типов). Фильтрация в views.py, сортировка и вёрстка в product_list.html работают с уже существующими полями модели Product (name и price) и структуру базы не затрагивают.

2. В чём разница между тегами {{ ... }} и {% ... %} в шаблонах Django?

{{ ... }} — тег переменной. Он вычисляет значение и выводит его в HTML (например, {{ product.name }} выведет название товара).
{% ... %} — тег управления логикой. Он задаёт циклы ({% for %}), условия ({% if %}) или служебные команды и требует закрывающего тега ({% endfor %}, {% endif %}).

{% endraw %}
3. Что произойдёт, если у двух товаров одинаковая цена при order_by('price', 'id')?

Сначала товары сортируются по цене (price). Если цены равны, Django применит второй критерий (id): товар с меньшим номером ID (добавленный в базу раньше) окажется выше в списке. Это гарантирует стабильный и предсказуемый порядок на странице.

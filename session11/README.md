# Занятие 11 · Фильтруем товары и оформляем каталог

15 ноября 2026. Продолжаем каталог Django из [занятия 10](../session10/README.md). К концу занятия каждый меняет условие или порядок сортировки и объясняет, почему список на главной изменился.

## Перед показом

Запустите свой проект из папки с `manage.py`. Убедитесь, что товар из админки виден на главной. Добавьте через админку ручку за 30 ₽, тетрадь за 80 ₽ и рюкзак за 500 ₽. Для предсказуемого результата используйте учебную базу с этими тремя товарами. Если в ней уже есть другие записи, учитывайте их при прогнозе.

Если проект не открывается, пройдите [проверку проекта и базы](../session10/README.md) до работающей главной и админки. В этом занятии используем текущую базу проекта. Модель товара и таблицы остаются прежними, поэтому для фильтра, сортировки и шаблона новые миграции не нужны.

## Шаг 1. Выбираем товары по цене

Перед показом спросите, какие из трёх товаров попадут на главную при цене до 100 ₽ включительно и что будет первым при сортировке от дешёвых к дорогим.

В `catalog/views.py` измените запрос в функции `home` по [образцу шага 1](01_catalog_home.py). Сохраните другие функции и маршруты. Обновите главную. Из трёх учебных товаров останутся ручка и тетрадь, именно в таком порядке.

- `filter(price__lte=100)` оставляет товары с ценой до 100 ₽ включительно. Это условие, как `WHERE price <= 100` в SQL.
- `order_by('price', 'id')` сортирует от дешёвых к дорогим. Если цены равны, первым идёт товар с меньшим `id`.

Для быстрой проверки добавьте товар ровно за 100 ₽. Он тоже должен появиться в списке.

## Шаг 2. Передаём выборку в HTML-шаблон

**Шаблон** — файл HTML, в котором есть места для данных и команды Django. Мы берём готовый `product_list.html` из материалов урока и кладём в приложение. При открытии главной Django вызывает `home` из `catalog/views.py`. Функция получает товары из базы и передаёт их шаблону.

```python
return render(request, 'catalog/product_list.html', {'products': products})
```

- `'catalog/product_list.html'` — имя шаблона. При `APP_DIRS=True` Django ищет его внутри папок `templates` установленных приложений. У нас полный путь от `manage.py` — `catalog/templates/catalog/product_list.html`. Первое `catalog` — папка приложения. Второе — подпапка для его шаблонов, чтобы их имена не пересекались с шаблонами других приложений.
- `{'products': products}` — данные для шаблона. Слева имя, под которым шаблон увидит список, справа выборка товаров из `home`.
- `{% for product in products %}` повторяет разметку для каждого товара, а `{{ product.name }}` подставляет название. Например, из `<span>{{ product.name }}</span>` получается `<span>Тетрадь</span>`. Браузер получает готовый HTML.

1. В приложении `catalog` создайте папку `templates`, внутри неё папку `catalog`. Скопируйте [product_list.html](templates/catalog/product_list.html) в `catalog/templates/catalog/product_list.html` относительно `manage.py`.
2. По [образцу шага 2](02_catalog_home.py) добавьте импорт `render` и замените только `home` в `catalog/views.py`. Оставьте импорт `HttpResponse`, если его используют другие функции.
3. Обновите главную. Те же товары и цены теперь показаны HTML-списком. Функция `home` передаёт шаблону выборку под именем `products`. Шаблон перебирает товары в цикле и выводит название и цену каждого.

Если Django пишет `TemplateDoesNotExist`, проверьте полный путь к файлу, обе папки с именем `catalog` и наличие приложения в `INSTALLED_APPS`.

## Самостоятельная проверка

1. При исходных трёх товарах предскажите результат для порога 50 ₽. Поменяйте предел в `home` и проверьте результат в браузере.
2. Верните порог 100 ₽. Спрогнозируйте, что изменится при `order_by('-price', 'id')`, затем проверьте.
3. Выберите порог ниже всех цен. На странице должно появиться сообщение «По этой цене товаров нет».

В конце каждый показывает результат и называет строку, которая задаёт отбор и порядок товаров.

## Шаг 3. Читаем бюджет из адреса

На главной по адресу `/` над карточками появится поле **«Бюджет до, ₽»**. В [шаблоне](templates/catalog/product_list.html) найдите `<form method="get">` и внутри неё поле `<input name="max_price" …>`. `name` — имя параметра в адресе. `id="max-price"` связывает поле с подписью `<label for="max-price">`.

Откройте [03_catalog_filters.py](03_catalog_filters.py) и замените только `home` в своём `catalog/views.py`. Возьмите шаблон из материалов занятия 11. Функция передаёт `show_budget=True`, и Django показывает блок с формой.

1. Сначала сами допишите `?max_price=60` к адресу главной. `request.GET.get('max_price', '')` прочитает строку `"60"`. `int()` превратит её в число, а `price__lte` отберёт товары до 60 ₽ включительно.
2. Вернитесь на главную. Теперь введите `60` в поле и нажмите «Показать». Браузер сам соберёт тот же адрес из имени поля и введённого значения. Товаров должно остаться столько же.
3. Нажмите «Сбросить». Адрес снова `/`. Параметра `max_price` нет, поэтому `get()` вернёт пустую строку, условие `if max_price` пропустит фильтр и вернётся полный список.

Диапазон 50–150 ₽ — отдельное упражнение на два условия в запросе. Для проверки формы поработайте с одной верхней границей, которую задаёт покупатель.

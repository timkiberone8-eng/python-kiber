## 2. Покупки, штуки и деньги — три вопроса

В `query_practice.py` меняй только SQL между тройными кавычками у `cursor.execute`. Остальной код, включая `fetchall()` и `print(row)`, оставь. **Ctrl+S → `python query_practice.py`** после каждого изменения.

Напиши запрос: по каждому товару показать число покупок, число штук и выручку. Самый денежный товар должен стоять первым.

Что нужно вспомнить: `COUNT(*)`, `SUM(quantity)`, `SUM(quantity * price)`, `GROUP BY`, `ORDER BY ... DESC`.

**До запуска посчитай одну строку руками:** воду купили один раз по одной бутылке и один раз по десять. Объясни, почему её покупки, штуки и выручка — разные числа.

<details markdown="1">
<summary>Подсказка: как собрать SELECT</summary>

После `product_name` нужны три вычисляемых столбца. Дай им имена `purchases`, `units`, `revenue` через `AS`. Имя после AS — название результата, а не дополнительный расчёт.

</details>

<details markdown="1">
<summary>Сверить запрос и результат</summary>

```sql
SELECT product_name,
       COUNT(*) AS purchases,
       SUM(quantity) AS units,
       SUM(quantity * price) AS revenue
FROM lesson8_practice_receipts
GROUP BY product_name
ORDER BY revenue DESC
```

| Товар | Покупок | Штук | Выручка |
|---|---:|---:|---:|
| Сэндвич | 1 | 3 | 450 |
| Сок | 3 | 4 | 400 |
| Вода | 2 | 11 | 220 |

Вода: 2 строки-покупки, `1 + 10 = 11` бутылок, `(1 + 10) * 20 = 220` рублей. `Decimal('450.00')` в выводе кортежа — нормальное точное денежное число.

</details>

Не меняя расчётов, поставь первым товар, которого продали больше всего **штук**. Затем товар, который покупали чаще всего. После опыта верни сортировку по выручке.

<details markdown="1">
<summary>Проверить изменение одной строки</summary>

`ORDER BY units DESC` — первой вода, 11 штук. `ORDER BY purchases DESC` — первым сок, 3 покупки. `ORDER BY revenue DESC` — первым сэндвич, 450 рублей.

</details>

## 4. От SQL до одного значения Python

Верни запрос задания 2 с четырьмя полями и сортировкой по `revenue DESC`.

В первой строке ответа — сэндвич. Нужно печатать название товара и деньги, без числа покупок и штук. В цикле пока стоит `print(row)`.

1. Не меняя SQL, замени печать так, чтобы она показывала товар и выручку для каждой строки.
2. Объясни, чем весь `result` отличается от текущей `row`.
3. Если все строки уже забрали первым `fetchall()`, что вернёт второй `fetchall()` без нового запроса? Покупки в таблице исчезнут?

<details markdown="1">
<summary>Ответ и объяснение</summary>

```python
for row in result:
    print(row[0], row[3])
```

Порядок задаёт SELECT: товар, покупки, штуки, деньги — индексы 0, 1, 2, 3. `result` — весь список из трёх строк; `row` — одна строка на текущем круге. Второй fetchall вернёт `[]`: строки ответа уже забрали, а исходные покупки остались в базе. Нового запроса не выполняли.

</details>

## 5. Своя четвёртая страница без диктовки

Запусти свой проект Django: в терминале перейди в папку с `manage.py` и выполни `python manage.py runserver`. Если проекта дома нет, начни с [конспекта](catch-up.html#django).

Добавь страницу **`/hobby/`** про вымышленное или настоящее увлечение. Поменяй только внутренний `urls.py`:

- новая функция `hobby(request)`, возвращающая `HttpResponse` с заголовком и коротким абзацем;
- один новый `path` внутри существующего `urlpatterns`;
- ссылка на увлечение с главной;
- ссылка «На главную» со страницы увлечения.

**Не заменяй весь файл готовым образцом:** сохрани уже работающие главную, `/about/` и `/contacts/`. Для контактов используй вымышленные данные.

Проверь кликами: главная → увлечение → главная → о проекте → главная → контакты. После каждого изменения Ctrl+S, затем обновление браузера.

<details markdown="1">
<summary>Подсказка без готовой страницы</summary>

Посмотри на `about`: новая функция устроена так же, а маршрут похож на `path("about/", about)`. В path имя функции пишется без скобок. Для ссылки HTML нужен `<a href="/hobby/">Моё увлечение</a>` внутри строки HttpResponse.

</details>

<details markdown="1">
<summary>Если совсем застрял: минимальное добавление</summary>

Функцию добавь **до urlpatterns**:

```python
def hobby(request):
    return HttpResponse("""
        <h1>Моё увлечение</h1>
        <p>Мне нравится придумывать головоломки.</p>
        <a href="/">На главную</a>
    """)
```

Внутри существующего списка маршрутов добавь `path("hobby/", hobby),`. В HTML главной страницы добавь `<a href="/hobby/">Моё увлечение</a>`.

</details>

### Найди ошибку без запуска

Один ученик написал:

```python
path("hobby/", hobby())
```

Почему это не то же самое, что `path("hobby/", hobby)`?

<details markdown="1">
<summary>Проверить объяснение</summary>

`hobby()` сразу пытается вызвать функцию, но ей нужен request. Здесь получим ошибку отсутствующего аргумента. В маршруте нужно передать **саму функцию**, чтобы Django вызвал её при запросе страницы.

</details>

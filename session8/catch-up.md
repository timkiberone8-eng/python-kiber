# Занятие 8: отладчик, покупки в базе и первые страницы сайта

Этот конспект поможет восстановить занятие 25 октября. Иди небольшими шагами: действие → запуск → проверка. Код можно скачать целиком, а затем разобрать по строкам. Если был на занятии и хочешь проверить себя, открой [задания для закрепления](practice.html).

Две независимые части: [магазин в PostgreSQL](#shop) и [сайт на Django](#django). Если дома не настроена база, можно начать с сайта. Пройденные на занятии запросы пока работают отдельно от сайта: вывод покупок на страницу ещё не делали.

**Как работать:** сначала запусти маленький пример с отладчиком. Затем выбери одну часть на сегодня. После каждого блока сравни результат с проверкой. Если настройка не получается за 10 минут, запиши команду и сообщение об ошибке и попроси тьютора помочь. Прочитать текст и самостоятельно запустить программу — разные результаты.

## 0. Где вводить команды и сохранять файлы

1. Открой в VS Code свою учебную папку. Для скачанных файлов создай в ней папку `session8_home`. Старые файлы не заменяй.
2. Открой **Terminal → New Terminal**. Команды `python ...` ниже вводятся в терминале, а код Python — в файле `.py`.
3. Перейди в новую папку: `cd session8_home`. Команда `dir` должна показывать её файлы. Если уже находишься в ней, повторять `cd` не нужно.
4. После изменения кода нажимай **Ctrl+S**. При запуске Python читает сохранённый файл.
5. Проверь `python --version`. Если команда не работает, сначала восстанови среду по [материалу занятия 6](../session6/practice.html), раздел «Что нужно дома».

Файл должен оканчиваться на `.py`, а не `.py.txt`. При скачивании по ссылке браузер может открыть текст: тогда сохрани его через Ctrl+S с указанным именем. Все команды ниже выполняются из папки, в которой лежат нужные файлы.

- `purchases` — список покупок в памяти Python. Само создание списка ещё ничего не записывает в PostgreSQL.

- `NOT NULL` — значение обязательно. Без значения и без значения по умолчанию запись отклоняется. Ноль — значение, а `NULL` означает отсутствие значения.
- `DELETE FROM lesson8_practice_receipts` убирает прежние строки этой таблицы. Таблица и столбцы остаются.
- Цикл `for purchase in purchases` берёт по одной покупке. `INSERT` записывает её в указанные четыре столбца. Четыре `%s` — места для четырёх значений второго аргумента `purchase`. Кавычки для SQL библиотека расставляет сама.
- Все команды курсору сдвинуты вправо относительно `with connection.cursor() as cursor:`. Вышли из этого блока — курсор закрылся.
- При успешном выходе из внешнего блока `with ... as connection` изменения подтверждаются. Если внутри возникла ошибка, эта транзакция откатывается. Здесь поэтому нет отдельного `commit()`.
- `connection.close()` закрывает подключение после выхода из обоих блоков.

## 4. Три разных вопроса к одним покупкам

После каждого изменения: **Ctrl+S → `python query_practice.py`**. Весь Python вокруг запроса оставляем.

### Сколько раз покупали товар?

Вставь вместо первого запроса:

```sql
SELECT product_name, COUNT(*) AS purchases
FROM lesson8_practice_receipts
GROUP BY product_name
ORDER BY product_name
```

`GROUP BY product_name` собирает покупки с одинаковым названием в группу. `COUNT(*)` считает строки в каждой группе. `AS purchases` даёт полученному столбцу имя «покупки». Это имя результата, оно не меняет таблицу и само ничего не считает.

**Проверка:** вода — 2 покупки, сок — 3, сэндвич — 1. Не считай бутылки вместо строк.

### Сколько штук продали?

```sql
SELECT product_name,
       COUNT(*) AS purchases,
       SUM(quantity) AS units
FROM lesson8_practice_receipts
GROUP BY product_name
ORDER BY product_name
```

`SUM(quantity)` складывает количества, `AS units` называет результат «штуки».

**Проверка:** вода — 2 покупки и 11 штук; сок — 3 и 4; сэндвич — 1 и 3. Ответ содержит три строки, по одной на товар.

### Сколько денег принёс товар?

```sql
SELECT product_name,
       COUNT(*) AS purchases,
       SUM(quantity) AS units,
       SUM(quantity * price) AS revenue
FROM lesson8_practice_receipts
GROUP BY product_name
ORDER BY revenue DESC
```

Умножаем количество на цену в каждой покупке, затем складываем внутри группы. `revenue` — имя выручки, `DESC` ставит большее число первым.

**Проверка:** сэндвич — 450, сок — 400, вода — 220. Всего 1070 рублей.

Без `AS purchases` подсчёт тоже работает. Если переименовать его в `AS purchase_count`, значения останутся теми же. Обычный `print(row)` печатает значения, поэтому название столбца в терминале не видно.

### Как читать результат в Python

Для последнего запроса строка устроена так:

| Индекс | Значение |
|---:|---|
| `row[0]` | товар |
| `row[1]` | число покупок |
| `row[2]` | число штук |
| `row[3]` | выручка |

Внизу файла можно заменить только цикл печати:

```python
for row in result:
    print(row[0], "покупок:", row[1], "штук:", row[2], "выручка:", row[3])
```

Получится, например: `Сэндвич покупок: 1 штук: 3 выручка: 450.00`. Этот цикл подходит **после последнего запроса с четырьмя полями**. Если в SELECT пока только товар и COUNT, `row[3]` не существует.

Проверь сам: замени последнюю строку SQL на `ORDER BY units DESC`, затем на `ORDER BY purchases DESC`. На первом месте окажутся вода и сок соответственно. В конце верни `ORDER BY revenue DESC`.

## 5. Запустить первый сайт на Django

Django — инструмент для создания сайтов на Python. Браузер запрашивает страницу, сервер получает запрос и возвращает ответ. Сейчас страницы работают **только на твоём компьютере**, покупки к сайту ещё не подключены. Для этой части PostgreSQL не нужен.

Если проект `mysite` уже создан на занятии, открой его и перейди в папку с `manage.py`. Второй проект поверх существующего создавать не нужно. Перед изменением `urls.py` сохрани его копию вне папки проекта.

Если проекта нет, в терминале из своей учебной папки:

```bash
python -m pip install django
python -m django --version
python -m django startproject mysite
cd mysite
python manage.py runserver
```

Вводи по одной команде. Если Django уже установлен в выбранном Python, первую можно пропустить. `startproject` создаёт папку и может ничего не напечатать. `runserver` запускай только там, где лежит `manage.py`.

Открой **http://127.0.0.1:8000/** в браузере. Должна появиться стартовая страница Django с ракетой. `127.0.0.1` значит «этот компьютер». Адрес не откроет твой сайт на телефоне или компьютере друга.

Терминал занят работающим сервером — это нормально. Для остановки щёлкни по терминалу и нажми **Ctrl+C**. Для нового запуска, оставаясь рядом с `manage.py`, снова введи `python manage.py runserver`.

Предупреждение про неприменённые миграции может появиться: для этих простых ответов без моделей оно не мешает. Если видишь traceback, а страницы нет, это ошибка, не обычное предупреждение.

## 6. Заменить ракету своим текстом

Открой **внутренний** `urls.py`:

```text
mysite/
    manage.py
    mysite/
        urls.py
```

Замени содержимое `urls.py`:

```python
from django.http import HttpResponse
from django.urls import path


def hello(request):
    return HttpResponse("Привет! Это мой первый сайт.")


urlpatterns = [
    path("", hello),
]
```

**Ctrl+S → обновить браузер.** Вместо ракеты появится приветствие. Сервер обычно подхватывает изменение сам; заново запускать `startproject` не нужно.

- `HttpResponse` создаёт ответ браузеру. `print` вывел бы текст только в терминал.
- `path` связывает адрес с функцией.
- `request` — запрос браузера, который Django сам передаёт функции. Пока его содержимое не используем.
- `return` возвращает ответ Django, а тот отправляет его браузеру.
- Пустой путь `""` — главная страница.
- `hello` в `path("", hello)` пишется **без скобок**: передаём функцию для будущего вызова.

**Проверка:** поменяй приветствие на своё. Сохрани и обнови страницу — текст изменился.

## 7. Добавить две страницы

Под `hello`, но **выше списка `urlpatterns`**, добавь функции:

```python
def about(request):
    return HttpResponse("Это страница о моём проекте.")


def contacts(request):
    return HttpResponse("Контакт вымышленный: Капитан Код.")
```

В **существующем единственном** списке маршрутов оставь главную и добавь ещё два пути:

```python
urlpatterns = [
    path("", hello),
    path("about/", about),
    path("contacts/", contacts),
]
```

**Ctrl+S.** Открой три адреса:

- `http://127.0.0.1:8000/` — главная;
- `http://127.0.0.1:8000/about/` — о проекте;
- `http://127.0.0.1:8000/contacts/` — контакты.

Проверяй адрес целиком: `/about/` отличается от `/`. Сама функция не создаёт адрес, пока в `urlpatterns` нет соответствующего `path`.

## 8. Сделать ссылки между страницами

Внутри `HttpResponse` можно вернуть HTML — разметку, которую браузер покажет как страницу. Замени **только функцию `hello`**:

```python
def hello(request):
    return HttpResponse("""
        <h1>Мой первый сайт</h1>
        <p>Здесь будет мой проект на Django.</p>
        <a href="/about/">О проекте</a>
        <br>
        <a href="/contacts/">Контакты</a>
    """)
```

Тройные кавычки позволяют записать строку на нескольких строках. `<h1>` — заголовок, `<p>` — абзац, `<br>` — перенос строки. У ссылки `<a href="/about/">О проекте</a>` адрес находится в `href`, видимый текст — между тегами.

В ответ функций `about` и `contacts` добавь обратную ссылку **внутри строки HTML**:

```html
<a href="/">На главную</a>
```

Например, вся функция `about` может выглядеть так:

```python
def about(request):
    return HttpResponse("""
        <h1>О проекте</h1>
        <p>Я учусь создавать сайты на Python.</p>
        <a href="/">На главную</a>
    """)
```

**Проверка:** главная → «О проекте» → «На главную» → «Контакты» → «На главную». Все переходы работают кликами. Можешь поменять тексты и вымышленный контакт, адреса пока оставь прежними.

## 9. Если не получилось

| Что видишь | Что проверить |
|---|---|
| `cursor already closed` | DELETE и цикл INSERT должны оставаться внутри `with connection.cursor() as cursor:`. Отступы — часть программы. |
| Ошибка у нескольких покупок в списке | После каждой записи `(...)` нужна запятая, дата целиком в кавычках: `"2026-10-20"`. |
| `UndefinedColumn` с `quantity` | Сверь имя в CREATE и INSERT. `quality` и `quatity` — другие имена. IF NOT EXISTS не исправляет уже созданную таблицу. Не удаляй её вслепую, покажи тьютору текст ошибки. |
| `UnicodeDecodeError` при `connect` | Ошибка может скрывать сообщение PostgreSQL. Сверь базу, пользователя и пароль с работающим входом в SQL Shell. Не переименовывай столбцы ради ошибки подключения. |
| `can't open file ...` | Проверь `dir`: находишься ли в папке файла, сохранён ли он с расширением `.py`. |
| `No module named ...` | Установи библиотеку через тот же `python -m pip`, которым запускаешь файл; проверь выбранный интерпретатор VS Code. |
| `manage.py` не найден | Перейди во внешнюю папку `mysite`, рядом с manage.py, а не во внутреннюю. |
